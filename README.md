# 面向高性价比组合的城市间多模式出行方案发现与多样性推荐

> 个人数据分析项目 · 以沈阳—成都为例
> 西南财经大学《数据分析与可视化》2026–2027 学年第一学期

## 这个项目是什么

城市间出行常被简化成"直飞还是高铁"的二选一。但把行程拆成两段自行拼接的联程组合，
例如"沈阳—北京高铁 + 北京—成都航班""沈阳—西安航班 + 西安—成都高铁"，
在部分日期反而更便宜，总耗时还能控制在 9–12 小时。

本项目要回答的是：**这些组合在哪一天、什么提前购票窗口、什么换乘条件下真正成立，
以及如何在时间、费用、便捷性与可靠性之间给出可解释的评价和多方案推荐。**

## 解决什么问题

- 现有工具各管一段：OTA 以机票酒店为中心，12306 只管铁路，地图只管市内接驳，
  航班动态产品只看准点率。用户想比较"高铁 + 航班"，只能在多个应用间来回切换、手工记账。
- 即使偶然发现便宜组合，也缺少对换站/换机场、行李重挂、误机无赔偿等风险的统一评估。
- 常规搜索倾向于给出一个"最优解"，而真实决策需要几个各有取舍的候选方案。

## 怎么做

1. **多模式图建模**（NetworkX）：节点是城市、机场、车站；边是航班、高铁、普速、市内接驳。
   接驳时间以缓冲区的形式建模，而不是固定常量。
2. **候选路径枚举 + 剪枝**：以候选枢纽（北京、西安、重庆、郑州、武汉）为中间点，
   枚举 2–3 段的组合，按耗时、费用、换乘次数剪枝，保留 k 条 Pareto 标签路径。
3. **多准则评价**：AHP 确定指标权重，TOPSIS 计算方案贴近度；指标含总费用、门到门时间、
   换乘次数、最小换乘缓冲、准点率、行李可直挂性、舒适度与碳排放。
4. **多样性推荐**：先取费用—时间 Pareto 前沿，再按"方案族"（直飞、空铁联运、双飞中转、
   高铁直达、组合接驳）分组，每组保留 1–2 个代表，保证 Top-K 覆盖不同选择逻辑。
5. **呈现**：Streamlit 面板展示方案卡片、Pareto 图与实时查询跳转（价格以 12306 / 航司页面为准）。

## 数据

- 只用公开可获取的时刻与价格**快照**，以及官方 API；不绕过验证码、不抓取个人信息。
- 价格快照按周采集，标注采集时间与数据版本；无法确认授权的数据只做小规模人工观察。
- 采用"离线快照 + 实时查询链接"，不承诺实时比价。

## 边界

- 最多 2–3 段组合。
- 不涉及自动购票、占座、支付、弃程（hidden city）、用户账户与个人画像。
- 网约车仅作为市内接驳方式，不作为跨城主力交通方式。
- 不做在线学习价格预测，权重由可解释的 AHP 给出，用户可切换偏好（省钱优先 / 时间优先等）。

```text
.\.venv\Scripts\activate

```

## 评估标准（开题报告口径）

在不少于 30 个测试日期上，至少 10% 的日期能找到比直飞便宜且总耗时不超过直飞 1.8 倍的组合；
Top-5 至少覆盖 3 种方案族；每条组合给出明确的换乘缓冲与风险标签。
